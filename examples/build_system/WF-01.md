# WF-01: config-aware cache maintenance

## Public contract (before implementation)

Each package optionally supplies UTF-8 configuration bytes in `config/<name>`
under `ALVA_BUILD_ROOT`. Missing file means the exact bytes `default`; an
explicit `default` is equivalent. Empty, whitespace and multiline configurations
are distinct values; no trimming. Existing but unreadable configuration is an
error, not a default. Manifests remain dependency lists.

The cache key includes source, configuration and current dependency outputs.
Configuration changes rebuild that package and its necessary reverse closure,
not unrelated/upstream packages. Repeated inputs hit across process restarts.
Output identity includes configuration. Only successfully promoted output may
publish a matching cached configuration. Interrupted builds must be retried.

New state records use format 2. Legacy or unknown-format records may supply
historical metadata but are never cache hits; a successful rebuild upgrades
them. Missing configuration identity also invalidates a cache entry. Preserve
B1–B11 unchanged. No concurrent input edits/build writers are newly promised.

## Pre-edit impact map

- `model.Package`: parser, three unit-test constructors, manifest creation,
  built/cached construction and dependency-output recording.
- `needs_build` and `engine.compute_output`: include configuration identity.
- `serialize_package` / `parse_package`: format and saved config identity.
- `store`: read optional configuration without swallowing read failures.
- `merge_state`: currently replaces live manifest entirely with historical
  record; preserve live dependency declarations while merging cache metadata.
- Build order, cycle rejection, staged promote and per-package persistence
  remain. Add external process tests for configuration, restart, legacy state,
  dependency edits and interrupted configuration replacement.

This is a development task, not an independent benchmark or a formal study.
