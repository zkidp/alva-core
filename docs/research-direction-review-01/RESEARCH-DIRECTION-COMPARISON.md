# Four directions, one decision standard

This is a qualitative decision, not a weighted score or publication forecast.
Evidence and source IDs: [SOURCES](SOURCES.md); collisions:
[gap matrix](PRIOR-ART-GAP-MATRIX.md). Status words follow the

## A — Agent Semantic Operation Validity

| Required question | Assessment |
| --- | --- |
| 1. Closest work | CodeStruct, SWE-agent/ACI, Serena; P26/P28/P32/P36 locally. |
| 2. Already solved | Structured action spaces, symbol retrieval, interface and feedback design are established. |
| 3. Independent unproved question | Does an existing-code *attachment* interface reduce disconnected/no-op work compared with equally documented existing tools? This is not currently identified as a missing primitive. |
| 4. Retain components | AEP/MCP, exact tools/docs, live body observer, controller, independent evaluator and sandbox. |
| 5. Must use `.alva`? | No. It supplies controlled stages; language unfamiliarity is a nuisance. |
| 6. Mainstream alternative | Python named-AST edits with Git snapshots and actual final tests; CodeStruct/Serena rather than deliberately brittle string-only baseline. |
| 7. Strongest baseline | Current Native with identical schemas/Skill and existing composition guidance; plus mature source-symbol editing. |
| 8. Minimum discriminator | Existing MM02/P36 attachment trace demonstrates feasible composition; a future matched maintenance task would need a preregistered interface-only change. No such change is justified now. |
| 9. Supporting result | Earlier valid target attachment and final behavior improvement on unseen maintenance tasks without extra answers/budget. |
| 10. Falsifier | No stage/behavior benefit or simple conventional guidance matches it; fewer discovery calls alone is insufficient (P28). |
| 11. New model calls | Would need at least a fresh pair to observe behavior, more for an effect estimate; **0 authorized**. Do not spend before identifying a treatment. |
| 12. Zero-model first? | Yes: existing operations' expressibility/attachment is already witnessed; no new gate rerun. |
| 13. External threat | Custom grammar, selected components, extra Skill content, familiarity and token censoring. |
| 14. Possible paper claim | Bounded maintenance-interface study, if independently compared; not yet an Agent correctness result. |
| 15. Prohibited | ALVA language superiority, “AST is new,” general utility from two successes, or function-generation failure as language impossibility. |

**Decision: PAUSE.** No new interface treatment currently has stronger support
than the exhausted discovery-tuning line. P37 qualification is not authorization
to run its model slots. E5/SS quantitative evidence is unavailable publicly here,
so it cannot be used to elevate this option.

## B — Shared-Graph Mutation Locality

| Required question | Assessment |
| --- | --- |
| 1. Closest work | Term graph rewriting, immutable DAG/tree transformation, AST refactoring, source patch locality. |
| 2. Already solved | Sharing, path/occurrence selection, reconstruction and copy-on-write are longstanding methods. |
| 3. Independent unproved question | Are node-addressed versus occurrence-addressed choices a recurring *Agent maintenance* hazard, beyond P33's particular implementation? |
| 4. Retain components | AIR inspection/identities, AEP reconnection, P34 scope guard, public evidence; no new compiler front end. |
| 5. Must use `.alva`? | To reproduce this specific shared AIR mechanism, yes; to study locality generally, no. |
| 6. Mainstream alternative | Source-tree occurrences or a persistent AST with explicit paths; Git diff supplies complete changed source. Need not invent Python AIR. |
| 7. Strongest baseline | Existing P35/P36 safe reconnection plus ordinary occurrence-selected source edit, independent scope/test checks. |
| 8. Minimum discriminator | An already existing public trace where the available unshared attachment is absent or ambiguous; none is established by MM02 now. A future study would need separately authorized evidence, not a replacement task search here. |
| 9. Supporting result | Repeated independently grounded locality hazards and a minimal method whose advantage survives correct conventional reconstruction. |
| 10. Falsifier | Existing compositions/source selectors provide the same locality at comparable burden; P35/P36 already falsify the claim that MM02 requires a new primitive. |
| 11. New model calls | 0 for a source/graph analysis; an Agent effect study later requires fresh paired runs, not authorized. |
| 12. Zero-model first? | Yes, but P33–P35 already establish the fixed case; do not rerun it as a new contribution. |
| 13. External threat | AIR deduplication/mutating-session design may create a problem normal source trees do not have. |
| 14. Possible paper claim | Precise shared-identity maintenance case study with observable enforcement and recovery compositions. |
| 15. Prohibited | Universal noninterference, new discovery of DAG sharing, generic path-copy novelty, or safe body scope as behavior proof. |

**Decision: SECONDARY, case-study synthesis only.** No new path-copy development.
This is the strongest current system-specific narrative, but not an established
new algorithm or a justified model expansion.

## C — Version-Bound Verification and Publication

| Required question | Assessment |
| --- | --- |
| 1. Closest work | Git CAS/ref transactions, required CI, OCC, refactoring transactions; P1 Python Guard. |
| 2. Already solved | Candidate identity, expected-base rejection, trusted check gating and private worktrees. |
| 3. Independent unproved question | Does program-granular identity improve verification reuse or avoid false conflicts beyond correct whole-candidate CAS? No evidence yet. |
| 4. Retain components | Authority store, transaction check, exact evidence capture, Guard; no new ledger. |
| 5. Must use `.alva`? | No; immutable Git objects can bind exact source candidates. |
| 6. Mainstream alternative | Isolated worktree, exact tree/test/environment digest, CI and atomic expected-old target-ref update. |
| 7. Strongest baseline | That complete Git/CI/OCC stack, including test on the exact candidate to publish; not “git diff” alone. |
| 8. Minimum discriminator | Future candidate replacement between check and publication on both systems; correct CAS should reject. This thought experiment is a parity control, not new science or an executed case. |
| 9. Supporting result | A specified useful guarantee or cost/false-conflict advantage absent from the complete source baseline. |
| 10. Falsifier | Same decisions/identity guarantees using conventional Git/CI under equal assumptions. No new threat after inspecting results. |
| 11. New model calls | 0 needed for concurrency/identity engineering; 0 authorized. |
| 12. Zero-model first? | Possible but not warranted as another generic CAS demonstration. |
| 13. External threat | Trusted Host/test/kernel assumptions; filesystem/platform crash behavior; validating one resource does not atomically update source and AIR. |
| 14. Possible paper claim | An integration/reliability artifact, or new granularity result only if a strong discriminator is first found. |
| 15. Prohibited | Hash/revision/transaction invention; arbitrary multi-agent safety; stale rejection equals successful recovery. |

**Decision: STOP as primary utility hypothesis; retain engineering.** P38 does
not test all concurrency hypotheses, but neither does it justify creating one.

## D — Evidence of Treatment Validity in Coding-Agent Research

| Required question | Assessment |
| --- | --- |
| 1. Closest work | ACI/CodeStruct interface studies, Verified Tool Calls, AFT, tau-bench, existing process/outcome evaluators. |
| 2. Already solved | Tool-call/argument metrics, postconditions, final-state tests and trace-based operational analysis. These are not new. |
| 3. Independent unproved question | For coding mechanisms, does object-bound evidence change the classification of **mechanism realization**, beyond a correctly implemented call+state+test baseline? Not: “are final tests useful?” |
| 4. Retain components | Existing frozen tool/dispatch/state records, target-body observer and authority identities; read-only analysis, not a new Agent harness. |
| 5. Must use `.alva`? | No. AIR gives unusually explicit intermediate observations but is not a necessary condition. |
| 6. Mainstream alternative | Immutable source snapshots, AST target diff, actual tool trace and CI tested tree identity; later external validation only if needed. |
| 7. Strongest baseline | Deterministic call trace reconciliation **plus** candidate target-state diff and independent tested/published identity. Not just count `ok:true`. |
| 8. Minimum discriminator | Four already frozen public situations: P24 exposed-vs-callable coverage, P26 HE23-B unchanged commit, P30 MM01-S blocked publication, P32 MM01-S correct publication. No new candidate or model. Detailed design next file. |
| 9. Supporting result | Additional correctly grounded distinctions survive the strong baseline without exposing ground-truth labels to the analyzer. At most an empirical measurement result. |
| 10. Falsifier | Baseline can make all distinctions with the same evidence; extra lineage only restates existing checks. Then abandon new-mechanism novelty and write the bounded case study. |
| 11. New model calls | **0** for the proposed first step. New model study unnecessary unless the measurement question first survives. |
| 12. Zero-model first? | Yes, design-only archived-evidence comparison; not executed here, and does not rescore history. |
| 13. External threat | Selection from ALVA failures, private trace completeness, expert/author labels, architecture-specific visibility, no prevalence denominator. |
| 14. Possible paper claim | Reproducible empirical taxonomy / measurement limitations, conditional on evidence and literature differentiation; not correctness improvement. |
| 15. Prohibited | All benchmarks confuse these layers; “first trace evaluation”; general causal mediation from observational traces; same-task success as effect estimate. |

**Decision: PRIMARY, bounded zero-new-model measurement feasibility only.** This
has the lowest incremental cost and an explicit parity stop rule. Novelty is
low-to-uncertain, not asserted. It is not a mandate for a new TOS/AEC product.

## Common qualitative comparison

| Dimension | A operation usability | B locality | C version publication | D treatment realization |
| --- | --- | --- | --- | --- |
| Novelty plausibility | Low broadly; narrow treatment undefined | Low algorithmically; case-study plausible | Low without new granularity problem | Uncertain; crowded measurement prior art |
| Strength of prior art | Strong direct agent evaluations | Strong classical theory/tools | Very strong mature practice | Strong tracing/operability; coding lineage comparison needs checking |
| Falsifiability | Good only after a treatment exists | Good with a real unmet locality case | Good but parity likely | Good: strongest baseline parity can end it |
| Existing evidence | Two successes plus multiple censored failures | Concrete failure, control, safe composition and real model success | Working publication, no advantage over Git | Multiple distinct failure stages, not prevalence data |
| Discriminating baseline | Hard to match interfaces/information | Correct occurrence/source reconstruction | Git+CI+CAS/OCC | Calls+target diff+tested/published identity |
| ALVA dependence | Moderate instrument; not necessary language | High fixed-case, low general question | Low | Low; retain AIR for internal controls |
| External validity | Weak custom-language tasks | Weak single shared-graph family | Broad applicability, no measured increment | Limited archives first, mainstream validation conditional |
| Solo engineering cost | High: new runs/treatment confounds | Low synthesis; high general rewrite engine | Medium/high, likely redundant | Low read-only first step |
| Reproducibility | Frozen stack possible, models stochastic | Strong deterministic records, archive availability limit | Existing mature tools; crash/platform scope costly | Public-record stage check feasible; missing raw yields UNKNOWN |
| Publication potential | Needs substantially better comparative evidence | Case study/system artifact, not proven new algorithm | Engineering report unless differentiated | Methods/case study possible, novelty must survive collisions |

No “all directions in parallel” recommendation. D first, B as synthesis fallback;
A paused, C frozen as engineering. Sunk effort is not an evaluation dimension.
