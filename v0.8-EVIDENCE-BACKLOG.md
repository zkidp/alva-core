## L1 - Record update semantics (confirmed language gap)

Evidence:
- Workflow priority task: one added field -> ~18 full-record construction
  sites, 50+ edit points mechanically propagated.
- Build system: `Package` 7 fields -> new record construction sites ~10
  (`load_manifests` / `build_one` x2 / `record_dep_outputs` /
  `parse_package` / tests etc.).

Status: **CONFIRMED CROSS-WORKLOAD** (>= 2 independent workload instances).

Candidate: partial record update preserving unspecified fields, updating only
named fields.
Do not decide syntax yet. First specify AIR / checker / codegen semantics.
(AEP side: an `update_fields(record_id, {field: value})`-style structured
operation.)

## GAP-009 - nested fold accumulator shadowing (compiler correctness bug)

- Symptom: inner fold referencing the outer accumulator -> codegen mapped all
  fold accumulators to the same Rust name `acc` -> inner `let mut acc`
  shadowed outer -> outer references resolved to inner empty vec ->
  **silently wrong result** (built empty -> report panic).
- Root cause: codegen variable naming layer (not lexical scope resolution, not
  IR binding identity - those layers were correct).
- M3 workaround: `replace_package` extraction (fold only references its own
  parameters).
- Fix requirement: minimal regression -> generic fix -> remove workaround ->
  B1-B11 full regression. No nested-fold special case.
- Status: **FIXED** (alva-lang `e7a85b1`, generic gensym fix; regression
  `tests/codegen/xfoldnest`; M3 workaround removed; B1-B11 full regression
  passes).
