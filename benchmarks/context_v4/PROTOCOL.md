# Compact context V4 prospective acceptance

8 November 2026. This is a new registration, not a replay or extension of the
consumed Host V3 study. Maximum twelve fresh slots, four tasks × T/V3/V4,
pair order balanced 2:2, concurrency one. Same DeepSeek Flash thinking/low
configuration and 8192 completion-output bound; each conversation observes
80 tools, 480 active seconds, 600,000 cumulative reported tokens, 20 seconds
cleanup grace. No replacement, additional user turn, generation retry or
operator repair. Provider uncertainty, runtime/SDK drift, isolation failure or
unconfirmed cleanup stops the schedule. Unknown usage/cost stays null.

Task selection is frozen in TASKS.json revision 3 before any model call. The
two rejected pre-model ordering drafts and correction reasons are retained in
[ENGINEERING.md](ENGINEERING.md); neither is a model outcome. H01/H02 are
previously engineering-qualified MM05/MM06 requirements, not previously tested
model targets; their build component was visible in earlier tasks. H03/H04 use
the unchanged public metadata program with a new component manifest, covering
archived retrieval and nonnegative pagination overflow. Four requirements,
two components; this is author-informed prospective testing, not independent
human holdout, an unseen-code guarantee or statistical confirmation. No input
renaming, preliminary sharing changes, task/assertion relaxation or result-based
task replacement is allowed.

All arms share the same current compiler, actual P34 authorization, independent
tests, source-proposal importer and Native publication/verification path. A
generic Result code-generation defect found during zero-model qualification is
fixed for every arm before freeze: Result parameters, let references and match
tails must not acquire an extra Ok wrapper. Source/AIR executable regression
tests and the existing conformance suite must pass. This is a new SDK/config,
not byte-identical execution of the historical V3 study.

V3 is a full-upfront-context baseline using the existing V3 mutation/Guard
configuration. It receives the full general Skill and original source initially.
V4 receives the dedicated compact official Host profile and public source paths,
then reads source only if needed. T receives the same compact profile/path input
as V4, submits exact source spans and uses the same protected import/publication
pipeline. Every arm has the same five advertised capabilities and unrestricted
access within the same allowlisted public source/document corpus; V3/V4 schemas
are identical, T differs only in its preparation argument. The initial loading
and response hints are the treatment, not information withholding. Full general
Skill/tutorials remain readable. T is not an external competitor or the previous
ten-tool Text workbench. This compares complete context/interface configurations.

References are generic compiler-checked grammar and sectioned public docs; no
task requirement is used to choose a recipe. V4/T get a small body-syntax hint
on read_target. Original source text and line endings remain exact; Native
source reads are explicitly import projections, T reads acknowledged text
proposals. No hidden evaluator, historical witness, trace or credential enters
model input or candidate mounts. Check/build/test execute in P22 Linux namespaces;
trusted Core parsing/publication executes in Host children. API access stays in
the Windows controller. Shared-UID nproc=512 profile is explicit.

Before generation, all twelve deterministic paths must establish original
task FAIL/regression PASS, then actual protected commit, fresh AIR and independent
task/regression/scope PASS. Freeze source/task/doc bytes, tool schemas, current
provider metadata, local/export code maps, compiler/rustc hashes, SDK trees and
preflight receipts in a separate commit. Verify runtime before/after each slot;
reserve this freeze once. Successful publication ends every slot immediately.

Two screens are fixed before outcomes: all twelve slots valid; at least three
both-success complete-usage pairs; V4 success count no lower than its control;
median V4/V3 reported-total ratio ≤0.90 and independently median V4/T ≤0.75.
Otherwise retain no favorable signal or the specific inconclusive disposition.
Include all failures/resources and separate input, cached input, output,
reasoning subset and reported total. Never subtract cached input from total or
double-count reasoning. Count submitted completion HTTP attempts separately
from unknown provider generation requests; attributable dollars remain null.
No token-count API calls, cache-outcome shortcuts or test modifications.
